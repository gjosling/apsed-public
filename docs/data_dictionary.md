# Data Dictionary: APSED Headcount Dataset

**Coverage:** June 2020 onwards
**Source:** Australian Public Service Commission APSED releases

---

## Output files

### `data/apsed_agency_jf.csv`

Headcount by agency × job family × snapshot date. Covers all releases from Jun 2024 onwards, as the agency-level cross-tabulation (Table 88) did not appear in APSED releases before Jun 2024. Generated by `pipeline/02_parse.py`.

| Column | Type | Description |
|--------|------|-------------|
| `snapshot_date` | date32 | Employment reference date (30 June or 31 December). Stored as `date32` in parquet; as `YYYY-MM-DD` string in CSV. |
| `taxonomy_regime` | string | Job family taxonomy version in effect for this release (see [Taxonomy regimes](#taxonomy-regimes)) |
| `agency` | string | Agency name as published in the APSED release, with the sub-agency "- " prefix stripped |
| `agency_canonical` | string | Canonical agency name matching the gazette dataset (e.g. `"Department of Agriculture, Fisheries and Forestry"`). Suitable for joining against the APS Gazette vacancies dataset `agency_canonical` column. Derived via a pipeline-maintained lookup table in `pipeline/utils.py` (`_AGENCY_CANONICAL`); agencies whose APSED name already matches the gazette are passed through unchanged. |
| `is_sub_agency` | boolean | `True` if this row is a sub-agency; `False` if it is a portfolio department row |
| `parent_agency` | string or null | Name of the parent portfolio department for sub-agencies; null for portfolio department rows |
| `job_family` | string | Job family label as it appears in the APSED release, normalised to canonical form (see notes) |
| `job_family_key` | string or null | SCREAMING_SNAKE_CASE job family key matching the gazette dataset `job_family` column (e.g. `ICT_AND_DIGITAL`). Null where no gazette equivalent exists: `Monitoring and Audit` (splits across two Regime 3 families), `Science and Health` (not disaggregable in 2a/2b/2b+), `Senior Executive` (no gazette equivalent), and `No data` (unclassified). |
| `headcount` | int32 or null | Number of employees in this agency × job family cell. Null means the source cell contained `"."` (most likely zero employees or not applicable). Stored as null rather than zero to preserve the source distinction. |

**Notes on `is_sub_agency` and `parent_agency`:**
Portfolio department rows (`is_sub_agency=False`) record only the direct employees of the core department. Sub-agencies listed under the same portfolio are separate rows with their own headcounts. Summing only portfolio department rows does **not** give the APS total; you must sum all rows.

`parent_agency` is null for portfolio department rows. In the parquet file this is stored as a proper null; in CSV it appears as an empty field. pyarrow's CSV reader requires `ConvertOptions(strings_can_be_null=True)` to read empty fields as null in string columns; pandas `read_csv` handles this correctly by default.

**Notes on `job_family`:**
The "unclassified" column label varies across releases. The pipeline normalises all variants to `"No data"`:

| Source label | Releases |
|-------------|----------|
| `No Data` | Jun 2024, Dec 2024 |
| `Zero Data` | Jun 2025 |
| `No data` | Dec 2025 |

### `data/apsed_totals_jf.csv`

APS-wide headcount by job family × snapshot date. Covers all releases from Jun 2020 onwards. Generated by `pipeline/03_parse_totals.py`.

| Column | Type | Description |
|--------|------|-------------|
| `snapshot_date` | date (YYYY-MM-DD) | Employment reference date |
| `taxonomy_regime` | string | Job family taxonomy version in effect for this release (see [Taxonomy regimes](#taxonomy-regimes)) |
| `job_family` | string | Job family label as it appears in the APSED release, normalised to canonical form |
| `headcount` | integer | APS-wide headcount for this job family. Always present (the totals table is not subject to suppression) |

**Note on Jun 2024 headcount jump:** From Dec 2023 (150,624) to Jun 2024 (185,343), the APS total increased by 34,719. Approximately 26,766 of this increase is attributable to the "No data" category being separately counted for the first time in the totals table. Underlying headcount growth for that period was approximately 7,953.

### `data/apsed_agency_headcount.csv`

Total headcount by agency × snapshot date. Covers all releases from Jun 2020 to Dec 2025. Generated by `pipeline/04_parse_agency_headcount.py`.

| Column | Type | Description |
|--------|------|-------------|
| `snapshot_date` | date32 | Employment reference date (30 June or 31 December). Stored as `date32` in parquet; as `YYYY-MM-DD` string in CSV. |
| `agency` | string | Agency name as published in the APSED release, with the sub-agency "- " prefix stripped. |
| `agency_canonical` | string | Canonical agency name matching the gazette dataset. Derived via the same lookup table as `apsed_agency_jf.csv` (`_AGENCY_CANONICAL` in `pipeline/utils.py`). |
| `is_sub_agency` | boolean | `True` if this row is a sub-agency; `False` if it is a portfolio department row. |
| `parent_agency` | string or null | Name of the parent portfolio department for sub-agencies; null for portfolio department rows. |
| `headcount_ongoing` | int32 or null | Number of ongoing employees. Null where the source cell contains `"."` (most likely zero; see notes). |
| `headcount_non_ongoing` | int32 or null | Number of non-ongoing employees. Null where the source cell contains `"."` (most likely zero non-ongoing staff; common at small agencies that have no non-ongoing employees). |
| `headcount_total` | int32 or null | Total employees (ongoing + non-ongoing). Null where the source cell contains `"."`. For active agencies this is almost always present; null values occur only for historical comparison rows that no longer existed at the snapshot date. |

**Notes on `is_sub_agency` and `parent_agency`:**
Same convention as `apsed_agency_jf.csv`. Portfolio department rows record only the core department's direct employees. Sub-agencies listed under the same portfolio are separate rows. Summing only portfolio department rows does **not** give the APS total; all rows (portfolio departments and sub-agencies alike) must be summed.

**Notes on null headcounts:**
The source table uses `"."` in cells where an employment type does not apply or rounds to zero. These are stored as null rather than zero to preserve the source distinction, consistent with the handling of `"."` cells throughout the pipeline. Null values in `headcount_non_ongoing` are common (small agencies with no non-ongoing staff); null values in `headcount_total` are rare.

**Note on complete headcount coverage:**
Unlike `apsed_totals_jf.csv`, this file counts all employees at every date, including those whose job family is unclassified. Before Jun 2024, unclassified employees (roughly 22,000–27,000 staff) did not appear in the job family tables; they are included here throughout. Summing `headcount_total` across all rows for a pre-Jun 2024 date will produce a higher figure than summing `apsed_totals_jf.csv` for the same date by approximately that amount. From Jun 2024, both files include the "No data" unclassified population and their APS-wide sums agree exactly.

### `data/crosswalk.csv`

Reference file mapping every observed job family label in each taxonomy regime to its Regime 3 (APSC 2025 Job Family Framework) equivalent. Committed to the repository.

| Column | Type | Description |
|--------|------|-------------|
| `regime` | string | Taxonomy regime: `1`, `2a`, `2b`, `2b+`, or `3` |
| `family_label` | string | Job family label as it appears in the source APSED release or in the output CSVs for this regime. Some entries are pre-normalisation source variants (for example `No Data`, `Zero Data`) that do not appear in the output CSVs; the pipeline normalises these before writing. |
| `regime3_family` | string | Corresponding Regime 3 (2025 JFF) family label, or `discontinued` if the family was dropped |
| `mapping_type` | string | Nature of the mapping (see values below) |
| `notes` | string | Additional context on the mapping |

**`mapping_type` values:**

| Value | Meaning |
|-------|---------|
| `same` | Label is identical in Regime 3 (no change) |
| `rename` | Same concept, different label |
| `merge` | This family merged with one or more others in Regime 3 |
| `split` | This combined family was split into two separate families in Regime 3 (e.g., Science and Health → Science + Health) |
| `split-precursor` | This family existed separately in Regime 1, was merged in Regime 2, and split back in Regime 3 (e.g., Science; Health) |
| `split-absorb` | This family was divided across two unlike Regime 3 families (e.g., Monitoring and Audit → Accounting and Finance + Compliance and Regulation) |
| `absorb` | This family was absorbed into a broader Regime 3 family |
| `discontinued` | This family was dropped before Regime 3 (headcount dwindled to zero) |

## Taxonomy regimes

The APSC's job family taxonomy changed across releases. The output columns `taxonomy_regime` and `family_label`/`job_family` reflect the taxonomy in effect at the time of each release. The `crosswalk.csv` file documents the label-by-label mappings between regimes.

| Regime | Releases | Family count | Coverage |
|--------|----------|-------------|---------|
| `1` | Jun 2020, Dec 2020 | 20 (22 labels - see note) | `apsed_totals_jf.csv` only |
| `2a` | Jun 2021–Jun 2023 | 19 | `apsed_totals_jf.csv` only |
| `2b` | Dec 2023 | 18 | `apsed_totals_jf.csv` only |
| `2b+` | Jun 2024–Jun 2025 | 19 | Both files |
| `3` | Dec 2025 | 17 | Both files |

**Note on Regime 1 label count:** Dec 2020 uses "Program" (American spelling) where Jun 2020 uses "Programme" for two families (`Development Programme`/`Development Program` and `Project and Programme`/`Project and Program`). Both spelling variants appear in the output and crosswalk with separate rows.

## Known limitations

**Science and Health disaggregation:** In Regimes 2a, 2b, and 2b+ (Jun 2021–Jun 2025), Science and Health employees are combined into a single "Science and Health" family. They cannot be separated for those periods. A continuous Science or Health series requires either excluding 2021–2025 or treating "Science and Health" as a combined category throughout.

**No data / unclassified employees:** The "No data" column represents employees whose job family was not classified in the source data. From Jun 2024 (when the agency × job family table first appeared), this has amounted to tens of thousands of staff (roughly 10–15% of the APS, varying by snapshot).

**Dot cells:** Some agency × job family cells in the source table contain `"."` rather than a number. These appear as `null` in `headcount`. `"."` and most likely represents zero employees or a not-applicable combination. Stored as null rather than zero to preserve the source distinction. The presence of null values means row sums across job families may not exactly match an agency's total headcount.

**Agency × job family coverage:** The `apsed_agency_jf.csv` file covers only the releases that include Table 88 (Jun 2024 onwards), as this cross-tabulation did not exist in earlier releases. APS-wide totals by job family are available for all releases via `apsed_totals_jf.csv`.
